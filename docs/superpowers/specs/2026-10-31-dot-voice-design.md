# Dot 网页语音最小接入

目标：在现有 Dots 网页中选择 Dot，使用当前设备麦克风进行实时语音，支持静音、挂断和异常清理。用户已要求继续推进此前推荐的“手机音频直连、桌面代理信令”方案。

方案：Mobile 插件维护通话状态、网页 WebRTC 和 HTTP 接口；Launcher 复用桌面登录态，仅代理白名单通话接口。音频不经 Mobile 网关。相比桌面采音转发，该方案能使用手机的麦克风；相比另建 API 助手，它保留当前 Dot 的上下文。

边界：本轮覆盖开发、受控测试、用户授权的本机原页面部署与真实通话验收，以及后续授权的提交、推送和正式发布；不改其他两台电脑。真实通话必须单列验收；官方内部接口的静态存在不代表手机建连成功。保留现有无关未提交文档。

契约：宿主状态新增 `voiceSignaling`；只放行 POST `/tbo/{id}/voice/calls` 和指定通话的 `attach`、`stop`。创建返回 SDP 文本及白名单响应头，旧 JSON 请求不变。Mobile 提供 `/api/dots/voice/{start,attach,heartbeat,stop}`，以随机 requestId 绑定账户、Dot 和通话，客户端不得任意指定原生 callId。同一网关最多一个未结束通话。

生命周期：创建不自动重试；重复 requestId 只复用同一输入结果。未知创建结果阻止新建，避免重复通话。取消可发生在创建返回之前，返回后补偿挂断。网页心跳与服务端超时租约清理已知通话；切换 Dot/设备、卸载、断网和失败都释放本地音轨。挂断失败保留可恢复记录并向用户报告。

网页要求：安全上下文与音频 API 可用；用户点击后请求麦克风，WebRTC 和数据通道就绪且 attach 成功后才显示已接通。首版只承诺前台通话，不承诺锁屏、后台保活或实时转写。

验收：固定路径与 SDP/响应头传递；取消竞争与未知写入；账户变化、重复创建、心跳过期；网页麦克风拒绝、晚到音轨、连接超时和断开清理；旧消息、附件回归；双仓库类型检查和构建。真实双向声音另外验收。
